# Changelog

Newest first. The number in the title is `modVersion` at the top of [mod.script.tl](best_before_1/content/mod.script.tl), which the game log prints at every load as `BEST_BEFORE version <number>` (between releases it reads the next number with "-dev", for example `1.2-dev`). Each entry's last line is the one-liner for the Changelog field of the in-game uploader ([how to upload](docs/publishing.md#uploading-an-update)). mod.io labels every file we upload "1.0" whatever the number here is, so the number in this file and in the log is the one that tells builds apart.

## 1.3 (30 Oct 2026)

- **New: non-perishable cargo can be paid differently.** Two in-game settings. "Non-perishable delivery time" (15 to 75 min, default 25 min): a cargo whose base delivery time (the time in its cargo file) is at least this counts as non-perishable, so at the default only food (meat, fish, vegetables, beverages, grain) is perishable. "Non-perishable cargo" (default Half bonus) says how the mod pays it: Full bonus (the whole curve, as up to 1.2), Half bonus (the curve with half its bonus, penalties in full), No bonus (penalties only) or No effect (normal game pay). Bulk cargo has delivery limits two to five times those of food, so on the logged runs it earned the full bonus on 92% to 100% of deliveries, which made the bonus a flat raise for it. **Saves already on the mod switch to Half bonus on their first load with 1.3** (the game gives a save the default of a setting it has not stored), so at the default curve their bulk cargo earns up to 110% instead of 120%; pick Full bonus in Load Game to keep the old pay. Stale Cargo warnings count non-perishable cargo in every case. Cargo from other mods is sorted by its own delivery time. Log: the arrival line gains `fileSeconds` and `perishable`, and reads `billing=none` for a unit the mod left alone. Asked for in issue #27.
- **Changed: the mod no longer replaces the game's cargo income function.** Up to 1.2 it swapped in a copy of the base formula that only logged what the engine passed in (pay unchanged), which clashed with any other mod that replaces that function. Neither way of paying needed it. The copy stays in the code behind a test switch, `incomeLogging` in `settings.tl` (off; read when the game starts). The log's start-up line now reads `BEST_BEFORE preRunFn: cargoIncomeScript left to the game`.
- **Removed: the `billing = "bookings"` fallback.** Ticket billing (since 1.2) is the only way the mod pays, so the setting in `settings.tl` and the code that booked a correcting entry to the company account after the game paid in full are gone. Nothing changes for a game on the shipped settings. The log no longer has `sending adjustment` lines, and the arrival line's `billing` field reads `ticket` (or `probe` under the test probe).

Release note: `New settings for non-perishable cargo, by default half the bonus (pick Full bonus in Load Game to keep the old pay). No longer replaces the game's cargo income function, so it clashes with fewer mods.`

## 1.2 (25 Oct 2026)

- **Changed: the bonus or deduction is part of the game's own pay.** The mod hands the game a pay multiplier for each delivered cargo unit before the game pays it (1 + the adjustment), instead of booking a separate entry to the company account afterwards. The game shares that pay along the unit's trip as usual, so every vehicle and line that carried the unit shows the change in its window and floating income numbers. A spoiled unit at the default settings now pays exactly nothing, and units whose buildings vanished in transit are no longer skipped. `billing = "bookings"` in `settings.tl` brings back the old way. Log: `ticketPrice` and `ticketItem` lines at `curve` and `full`; the arrival line's `deduction` and `bonus` are now an estimate from the predicted pay, marked `billing=ticket`.
- **Changed: freshness runs out at the game's own delivery limit.** The mod used 1.5 times the cargo's delivery time from its file; it now asks the game for the cargo's adjusted delivery time, the limit the cargo bar in a vehicle's window runs against. That limit shrinks as the game years pass: 1.5 times in 1900, falling 0.00625 a year to 0.75 times in 2020, and 0.75 times from then on. So on any save past 1900 the mod rated cargo fresher than the game does, a few points in the 1910s and far more in later eras, paying too much bonus and warning too little. If the game cannot answer, the mod falls back to 1.5 times. The arrival log lines carry `limitFrom=adjusted` or `limitFrom=file`.
- **New: the stale threshold is an in-game setting.** "Warn on cargo below freshness percent", 0% to 25% in 5% steps, default 10%. A unit below it, or spoiled, counts as stale for the Stale Cargo warning. It used to be half of the "normal pay at freshness" setting, so it moved when the pay curve was changed; now it does not. `staleShareOfBreakeven` in `settings.tl` is gone. The warning text says "below the mod's stale freshness setting".
- **New: the Stale Cargo warnings can be turned off in game.** A check box, "Show Stale Cargo warnings" (on by default), next to the other settings. Unticked, it takes down every warning shown and forgets the lines' history. Untick it, load and save before removing the mod from a save: the game keeps a shown warning in the save, and a save that holds one stops with "Failed during startup" when loaded without the mod (1.0.1 too). Steps: [docs/removing-the-mod.md](docs/removing-the-mod.md). `staleWarnings` in `settings.tl` is now only its fallback.
- **New: `deliveryLimit` log lines.** At `curve` and `full` the log gets one line per cargo type, with the game year, the cargo file's delivery time, the game's adjusted delivery time and their ratio, whenever one of them changes and at least once a game month. For testing how the limit follows the year and the difficulty settings ([docs/future/delivery-limit-tests.md](docs/future/delivery-limit-tests.md)); pay is unchanged.
- **New: `lineName` log lines.** At `curve` and `full` the log gets the line's entity id beside its name once a game month for every line the Stale Cargo warning tracks, so the ids in the arrival lines (`staleLine=`) read as names.

Release note: `Bonus or deduction now part of the game's own pay, so lines and vehicles show it. Freshness uses the game's delivery limit. Stale warning threshold and on/off switch added to the settings.`

## 1.0.1 (18 Oct 2026)

- **Fixed: the game would not start with the mod.** The 1.0 file list (`_content.json`) left out `settings.tl`. The game builds its file index from that list, so the mod's first script failed with "module 'best_before_1::/settings.tl' not found" and the game answered "Could not initialize game: try removing the mod". 1.0 never loaded for anyone.
- **Fixed: the file list is checked.** `tools/check_content_list.py` fails if `_content.json` and `content/` differ; it is part of the upload steps.
- **Fixed: a missing `settings.tl` can no longer stop the game.** Both scripts load it under `pcall` and fall back to built-in numbers that mirror it; the log says so (`BEST_BEFORE settings.tl could not be loaded`).
- **New: "Stale Cargo" warnings.** A line whose deliveries are mostly stale gets a warning in the notification log and on the line; it clears when the line recovers. Rule and settings: [docs/stale-line-warnings.md](docs/stale-line-warnings.md). Turn off with `staleWarnings = false` in `settings.tl`.
- **New: version line in the log**, so a log shows which copy of the mod ran (the published mod and a `staging_area` copy share the id `best_before_1`).
- Also: a warning that fails to send is retried at the next roll and taken down once when the warnings are off; more stale-line log lines (the threshold in force, the stops before and after a reset).
- **Oddity: the uploaded file calls itself 1.1.** The file on mod.io was uploaded while this release was still numbered 1.1, so the log of the published copy prints `BEST_BEFORE version 1.1`; a log that says 1.1 is this release. The code is the same as the 1.0.1 commit apart from that one string (`modVersion` in the repo is `1.0.1`). The next release was numbered 1.2, so the log line is unambiguous again.

Release note: `Fixes the game not starting with the mod. Adds Stale Cargo warnings for lines that mostly deliver spoiled cargo.`
